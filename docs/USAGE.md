# Руководство по `wssh`

Запуск без аргументов открывает **интерактивное меню** — самый удобный способ. Ниже —
и меню, и эквивалентные команды для скриптов/быстрого доступа.

```bash
wssh            # меню
wssh --help     # список команд
wssh <команда> --help
```

Почти всё резолвится по имени и по нечёткому поиску: если имя не точное, `wssh` предложит
выбор. Без TTY (в пайпах/CI) интерактивные команды аккуратно сообщат, что нужен терминал.

**Навигация в любом списке/меню.** Везде используется один и тот же выбор с хоткеями:

- печатайте — список фильтруется на лету;
- `Tab` — переключение сортировки (где применимо);
- `↑/↓` — перемещение, `Enter` — выбрать;
- `Esc` или строка «← Назад» — вернуться на шаг назад / выйти из меню, ничего не выбирая.

Смайлики остались только в баннере и заголовках секций — сами строки списков ровные,
без иконок, чтобы колонки не «прыгали» в разных терминалах.

## 🖥 Серверы = `~/.ssh/config`

Сервер — это сохранённое SSH-назначение для **интерактивного входа** (шелл), не туннель.
**Серверы хранятся прямо в `~/.ssh/config`** — это единый источник правды: каждый сервер
есть `Host`-блок (имя сервера = алиас). То, что обычный ssh-конфиг выразить не может —
описание, теги, выбор «пароль» и ссылку на сохранённый пароль — `wssh` держит в комментарии
`#wssh {…}` прямо над блоком. Статистика (когда использовали, сколько раз) лежит отдельно в
`~/.wizard-ssh/usage.json`, чтобы не переписывать конфиг на каждое подключение.

```bash
wssh server add               # мастер: алиас (= Host), HostName/User/Port, авторизация, описание, теги
wssh server ls                # таблица; --sort recent|name|uses|created|updated [-r] [--json]
wssh server connect <имя>     # войти в шелл (alias: wssh s c <имя>)
wssh server edit <имя>        # поэлементный редактор (пишет в ~/.ssh/config)
wssh server rm <имя>          # удалить Host-блок (без имени — мультивыбор)
```

Способы авторизации: `agent` (ssh-agent/по умолчанию), `key` (записывается как `IdentityFile`
в блоке), `password` (можно сохранить в зашифрованном хранилище — см. ниже; в `#wssh`
попадает только ссылка на секрет, не сам пароль).

Любой Host-блок из `~/.ssh/config` (в т.ч. написанный вами вручную) виден как сервер и
доступен для подключения. Одно-алиасные блоки в основном файле можно редактировать и удалять;
мульти-алиасные блоки, `Match` и хосты из `Include` — **только для подключения** (их `wssh`
не трогает). Перед любой записью создаётся бэкап в `~/.wizard-ssh/backups/`.

> **Миграция.** При первом запуске после обновления прежний `servers.json` автоматически
> переносится в `~/.ssh/config` (с бэкапом конфига), статистика — в `usage.json`, а сам файл
> переименовывается в `servers.json.migrated` (не удаляется).

## 🚇 Туннели

```bash
wssh tunnel add               # мастер: куда (как у серверов) + тип проброса + порты + имя
wssh tunnel ls                # таблица со столбцом «Тип» (-L/-R/-D и схема портов)
wssh tunnel connect <имя>     # поднять туннель (alias: wssh t up <имя>)
wssh tunnel edit <имя>        # менять имя/описание/теги/подключение/проброс/авто-браузер
wssh tunnel rm <имя>
```

Типы проброса:

| Тип         | Флаг                                 | Что делает                                                     |
| ----------- | ------------------------------------ | -------------------------------------------------------------- |
| **Local**   | `-L localPort:remoteHost:remotePort` | открыть удалённый сервис у себя (`http://localhost:localPort`) |
| **Reverse** | `-R serverPort:localHost:localPort`  | **открыть локальный сервис на сервере**                        |
| **Dynamic** | `-D localPort`                       | SOCKS5-прокси на локальном порту                               |

Для Local-проброса можно включить авто-открытие браузера. Туннель держится, пока не
нажмёшь `Ctrl+C`. Если проброс/коннект падает сразу — будет подсказка (занят порт,
нет доступа и т.п.).

В интерактивном меню туннелей есть пункт **«Создать и сразу поднять»**: выбираешь хост
из `~/.ssh/config`, задаёшь проброс — туннель сохраняется и тут же поднимается, без
отдельного шага подключения.

Для хостов, которых нет в `~/.ssh/config`, есть подменю **«Временные туннели»** (или
`wssh tunnel temp`): вводишь хост/IP, пользователя, порт и проброс вручную, туннель
поднимается сразу. Такие туннели хранятся в **отдельном списке**
(`~/.wizard-ssh/temp-tunnels.json`), не смешиваясь с основными, — их можно поднимать,
редактировать и удалять из того же подменю.

Пример обратного туннеля: «пробросить локальный dev-сервер :3000 на сервер :8080» —
тип Reverse, порт на сервере `8080`, локальная цель `localhost:3000`.

## 🗂 `~/.ssh/config` (то же, что серверы)

Серверы и есть хосты `~/.ssh/config`, а в интерактивном меню это один общий раздел.
Команды `wssh config …` дают «сырой» доступ к файлу — удобно для полей, которых нет в
мастере серверов (`ProxyJump` и любые другие опции). **Перед каждой записью — бэкап** в
`~/.wizard-ssh/backups/`, а аннотация `#wssh {…}` над блоком сохраняется при правке.

```bash
wssh config ls                # таблица: Alias / HostName / User / Port / IdentityFile
wssh config add               # Host + HostName/User/Port/IdentityFile/ProxyJump
wssh config edit <alias>      # правка полей (прочие опции и #wssh сохраняются)
wssh config rm <alias>        # удалить блок
wssh config connect <alias>   # войти в шелл по алиасу (= подключение к серверу)
```

Автоматически управляются только одно-алиасные `Host`-блоки в основном `~/.ssh/config`.
Хосты из `Include`/`Match`/мультиалиасных блоков показываются в списке, но авто-удаление
и правка для них отключены — доступно только подключение.

## 🔌 Подключение и поиск

```bash
wssh connect <имя>            # ищет среди серверов, туннелей и алиасов конфига и подключает
wssh connect                 # нечёткий выбор из общего списка
wssh search <запрос>          # единый поиск по всем спискам; затем можно сразу подключиться
```

Поиск нечёткий (по имени, описанию, хосту, пользователю, тегам, алиасу).

## 🛠 Действия по SSH

```bash
wssh check <имя>              # TCP-проверка доступности (хост:порт), с задержкой в мс
wssh copy-id <имя>            # ssh-copy-id: установить публичный ключ на сервер
wssh run <имя> -- <команда>   # выполнить команду на сервере, напр.: wssh run web -- uptime
wssh transfer <имя>           # scp ИЛИ rsync: загрузка/скачивание (мастер выбирает инструмент)
```

Для `transfer` мастер спрашивает инструмент: **scp** (простое копирование, опция «рекурсивно»)
или **rsync** (дельта-синхронизация; опции: архив `-a` по умолчанию, сжатие `-z`, `--delete`,
пробный прогон `--dry-run`). rsync ходит через тот же SSH-транспорт (порт/ключ/алиас/пароль).

`run` передаёт всё после `--` как команду. Для `copy-id`/`transfer` пароль берётся из
хранилища (если сохранён) или спрашивается.

## 🔐 Хранилище паролей

Пароли SSH (для авторизации по паролю) можно сохранять — они шифруются **AES-256-GCM**,
ключ выводится из мастер-фразы алгоритмом **scrypt**. Мастер-фраза вводится один раз за
сессию и хранится только в оперативной памяти; на диск пароли в открытом виде не пишутся.

```bash
wssh vault                    # статус и управление
```

В меню `vault`:

- **Создать хранилище** — задать мастер-фразу (и, на macOS, включить Touch ID).
- **Разблокировать / Заблокировать** — ввести фразу / сбросить сессию.
- **Сменить парольную фразу** — перешифровать все секреты.
- **Показать сохранённый пароль** — выбрать сервер/туннель и (после подтверждения и
  разблокировки) увидеть его пароль на экране; при возврате в меню экран очищается.
- **Удалить сохранённый пароль** — у выбранного сервера/туннеля; сам сервер/туннель
  остаётся, пароль просто спросят заново при следующем подключении.
- **Сбросить хранилище** — на случай забытой фразы: удаляет `vault.json` и все
  сохранённые пароли (серверы и туннели сохраняются). После этого можно создать
  новое хранилище с новой фразой.
- **Включить / выключить Touch ID**.

При добавлении/редактировании сервера или туннеля с авторизацией «Пароль» спрашивается
«Сохранить пароль в зашифрованном хранилище?». Если да — при подключении пароль
расшифруется автоматически (после разблокировки хранилища).

### Touch ID (macOS)

Если включён, биометрия разблокирует ключ хранилища, лежащий в Keychain. Требуются macOS,
датчик Touch ID и Xcode Command Line Tools (`swiftc` — крошечный helper компилируется один
раз и кэшируется в `~/.wizard-ssh/bin`). Если что-то недоступно — спокойный откат на ввод
мастер-фразы.

**Компромисс безопасности:** Touch ID здесь — слой удобства поверх мастер-фразы. Ключ
хранится в твоём login Keychain, а корнем доверия остаётся мастер-фраза. Для максимальной
строгости не включай Touch ID и вводи фразу каждую сессию.

## 📦 Экспорт / импорт

```bash
wssh export                   # в ~/.wizard-ssh/wizard-ssh-export-<ts>.json
wssh export /путь/backup.json
wssh import /путь/backup.json            # добавить к существующим (безопасно)
wssh import /путь/backup.json --replace  # заменить все списки
```

В бэкап входят серверы, туннели, настройки и **зашифрованное** хранилище (`vault.json` как
есть — пароли остаются зашифрованными; на новой машине понадобится та же мастер-фраза).
Локальное непустое хранилище при импорте не перезаписывается.

## ⚙️ Настройки и данные

```bash
wssh settings                 # пользователь/порт/авторизация/удалённый хост/браузер/сортировка по умолчанию
wssh path                     # путь к ~/.wizard-ssh
```

`wssh settings` — это меню: текущее значение каждой настройки видно прямо в списке,
выбираешь одну строку и правишь только её, остальные не трогаются. `Esc` — выйти.

Изолировать данные (например, для теста): `WIZARD_SSH_HOME=/tmp/wssh-test wssh ...`.

## 🧯 Поведение при ошибках

- Нет `ssh`/`sshpass`/ключа/файла — понятное сообщение, без падения.
- Быстрый обрыв туннеля — подсказка о занятом порте / доступе.
- `Ctrl+C` — аккуратный выход (код 130); закрытие туннеля штатно.
- Повреждённый файл данных — бэкап + чистый старт с предупреждением.
- Неинтерактивный запуск интерактивной команды — сообщение «нужен TTY», код 1.
